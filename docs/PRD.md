# PRD · Product Requirements（产品需求）

> 本文件是"产品必须做什么"的唯一权威出处，只写预期。
> 用语：**做** = 必须实现；**不做** = 明确排除；**边界** = 平台/技术边界内给替代路线。

## R0 总纲

- **R0.1** Web 应用·单管理员：浏览器直接可用的界面（不做 CLI），登录门禁 +
  凭证平台统一配置（详见 R11；多租户/积分不在系统范围，tenant 机制退化为单租户兼容层）；
  单机部署起步，架构不锁云。**做**
- **R0.2** 范围 = 选题 → 口播脚本 → 公众号长文 + 公众号发布登记/48h 回流；
  视频成片（R4/R10）与发布台（R6）不在系统范围。**做**
- **R0.3** 公众号不自动发布；一切发布动作人工执行，系统只做物料与台账。**不做**
- **R0.4** GLM 为主 LLM（写作模型可切换），单通道、不保留备选 LLM 通道开关。**做**
- **R0.5** 视频剪辑**不做**：数字人成片（R10）不在系统范围，不做剪映草稿/模板剪辑路线。**不做**
- **R0.6** 同行发现 = 自建账号扫描。**做**
- **R0.7** 能复用开源就不自研。**做**
- **R0.8** 内容定位：FDE 三条业务线（企业主 AI 培训获客 / FDE 项目交付 / FDE 人才培训），
  每条内容落到"可验收"视角；周节奏 **5 条+ 口播短视频 + 2 篇+ 公众号长文**（高产能设计）；
  业务线**交付项目优先**（内容优先展示交付案例拉项目询单）；主战场**抖音优先**、视频号同步；
  **不刻意做 CTA**（转化动作自然发生，系统不内置引导话术）；
  **能用里程碑 = 带来第一个真实客户线索**。
  每题双受众（企业主 boss / 准FDE fde / 双受众 both）。**做**

## R1 选题库

- **R1.1** idea 深研：一句话 → 联网检索 → **深度研究报告（2000 字+，含更多案例与信源）**
  → 0-10 打分 + 钩子候选。
- **R1.1b** 快速记选题：不触发 LLM 的快速入库入口，事后可再深研。
- **R1.1c** 相似选题自动合并：同行拆解/多来源产生的相似主题候选，入库时自动检测
  与已有选题的相似度并标记/合并，减少重复入队。
- **R1.2** 全网热榜雷达（DailyHotApi/TrendRadar 类）。**不做**——大众热搜与本业务获客无关；
  "借势"的正确来源是**同行热门视频监控**（R3）。
- **R1.3** 同行视频拆解产出选题候选（钩子/叙事结构/可复刻点/选题价值）；候选标题与近 14 天已有选题相似 ≥0.55 时**不入库**（analysis 记 topic_candidate_suppressed）——不同同行视频产出同一角度是选题趋同的主通道。
- **R1.4** **今日靶子=观点怼热点**（三方向「123都要」，半句话判决形态；本条为需求总账，
  实现契约见 TDD §6 靶子产线）：
  **①热点落饭碗**（trending_daily 每日 6 点）：六路原料（百度热搜 50/抖音热点榜 50/知乎 30/
  科技媒体 RSS 六源+GitHub 新库+AIHot 48h/对标圈近 2 天=议题参考禁止当热点/已发视频清单=冷饭判据）
  ×租户画像→ LLM 产 ≤6 个**半句话判决靶子**（sentence ≤16 字+context+heat+spice），
  过程序闸（科技词闸/半句话闸/劝告开头闸/预言腔负向闸/判词词根闸）+成色终审法官闸
  （trending_target_judge，正样本=已发标题标尺，判不过物理删）+硬校验（对标圈拦截/
  14 天判决句撞车/冷饭闸≥0.55/批内去重）落人设号选题库（source_type=trending，draft）。
  **②一线交付爆料**（self_story_daily 每日 6 点）：已发视频清单（60 条）盘 franchise 三类靶
  （断更系列续集/实训营时间线续集/受众关心零覆盖空白带），冷饭闸 ≥0.75，≤3 条。
  **③实测打假**：待实测清单（规划方向，暂无执行器）。
  通用裁定：判词=带罪名的控诉不是预言（预言腔四词根废靶）；判词里带菜单里最狠的数字；
  阵营=用户/工厂人 vs 巨头/精英主义；判据不用问人——已发视频清单本身就是冷饭判据；
  同一事件实质新进展=合法续集；批次替代（当日无下游的旧 draft 让位）；无可怼=诚实空过不挂失败。
  首要目标=1980 线下实训营报名。承接哲学=人设优先、不刻意承接；辣度不设限；
  半句话形态=三秒点名+一句判词。
- **R1.5** 审阅交互：队列式逐条 定审/否决/跳过 + 键盘 A/S/X/Esc + 自动下一条；
  计数 chips 筛选、批量定审/否决、NEW 徽标、相对时间；表格存档行内可审、点行展开。
- **R1.6** 发布数据反哺选题评分。**不做**——评分只由内容本身决定；
  发布数据不进系统台账（见 R6）。
- **R1.7** 检索降级必须可见：命中条数或未生效原因展示在选题详情。
- **R1.8** **话题雷达**（抖音话题监控，区别于 R1.2 否决的大众热榜；话题面并入每日热点调度，
  无独立页面，`/api/radar` 仅保留查看域端点）：每日 6 点随热点雷达调度（trending_daily）巡检
  指定话题的新视频（去重），命中**低粉高赞**（硬阈值：粉丝<10万、赞粉比≥2）按 R3.7 质量闸
  自动进拆解库；雷达话题 ID 全局唯一（库级 unique 约束）。

## R2 脚本工场

- **R2.1** 口播脚本生成（**一版精品直出**，质量优先于选择）：**按选题类型自动选择最合适的一个范式**
  （悬念/数字/反共识为基础范式库，可扩展）；篇幅两档——**240~320 字（50~70 秒黄金档，默认）**
  与长版 600~900 字（2~3 分钟，视频号场景），生成时可选；
  硬约束=前 3 秒钩子点名受众+痛点、中段可验证证明（案例/数字/交付物）、
  **结尾自然收尾（不刻意 CTA，禁引导话术）**、
  **合规红线（写死）：禁绝对化承诺（最好/第一/保证收益等）、禁夸大宣传、实事求是**、
  **人设回扣（写死）：每条的证明环节必须落到可验收交付（验收单/可量化结果）**。
- **R2.2** 口播结构模板库 CRUD（默认模板 hook→pain→solution→proof→cta；选用走显式 template_id）。
- **R2.3** 批判打磨：刻薄评审挑刺并重写，可反复；critique 追加进 notes；
  **生成后自动先打磨一轮**再进定稿队列（仍可手动追加）——一版精品制下打磨是唯一质量杠杆，
  预算全给打磨。
- **R2.4** 定稿三产物：提词器文本（`/`停顿、`**`重音、按呼吸分段）、
  分镜（≥3 镜头含 B-roll 关键词）、标题候选（抖音×2 / 视频号×1 / 封面大字≤12 字）。
- **R2.5** 定稿交互：单版呈现（历史旧数据仍可对比），A 定稿 / P 打磨 / S 跳过。

## R3 同行监测与拆解库

- **R3.1** 同行账号管理与监测（独立「同行监测」页，拆解库页只管作品审阅）：
  账号增删改查与启停；单号扫描 + 一键全量扫描；上次扫描时间与扫描历史
  （路线/降级原因必须可见）；账号实测评分展示（相关性/质量/综合，
  质量分 <7.5 移除监控，口径见 TDD §5）；每号拆解统计联动（近 7 天/累计）。
  添加账号支持**链接自动识别**：贴视频或主页链接，自动反查昵称与主页回填。
- **R3.2** 扫描主路线免登录：贴作者任意一条视频链接（锚点视频模式）
  或主页链接；下载与列表全部走浏览器拦截；降级原因必须可见。
- **R3.3** 贴链接在线拆解（免登录）+ 本地视频/音频上传拆解。
- **R3.4** 扫描发现的账号新视频**全量自动拆解**（无条数上限），按视频 ID 去重。
  **拆解完即删**：媒体文件在拆解成功后自动删除（重拆解自动重新下载，本地原文件删后需重新上传），
  磁盘不随拆解量无限增长。
- **R3.4b** 拆解报告增加**数据归因**维度：结合播放/点赞等数据拆解"为什么这条爆"。
- **R3.4c** **定时自动扫描**：系统按计划周期自动执行同行扫描（无需手动点），
  依赖定时任务框架（见 X10）。
- **R3.6** **关键词发现对标账号**：添加账号支持「搜账号」模式——输入关键词+方向，
  搜索引擎挖出抖音相关视频（绕开平台搜索登录墙）→ 免登录 反查作者与粉丝数，
  按粉丝数排序产出候选清单（持久化，待定夺/已加入/已忽略）；一键加入监测清单
  （分享主页链接，扫描链路直接可用）；已在清单的自动标记，已忽略的不重复推荐；
  风控样本自动跳过且原因可见。热门排序用真实粉丝数，不消耗 LLM。
- **R3.7** **质量闸全自动拆解**：扫描发现的同行新作品按互动闸自动批准进拆解——
  **评论数 ≥ 门槛 或 赞数 ≥ 门槛，任一满足即拆**
  （两道门槛设置页可调，默认 评论 20 / 赞 300；播放数平台匿名通道拿不到，不进闸线），
  未达标行保留待定夺（标 ignored，手动批准可强制拆）；样本热度分=评论/2+赞/60 封顶 10，
  与闸线同源回写。（下载→ASR→LLM→选题候选自动进选题库 draft。）
  话题雷达「低粉高赞」命中同口径自动进拆解，已在库不重复。拆解库日常无需人工巡视。
- **R3.8** **两类号策略与拆解分叉**（类型是**内容本身**
  的属性，拆解/选题时即判定，与账号粉丝量无关）：拆解 prompt 为**双模式判定式**——LLM 先
  判 content_type（leadgen=引导密集的获客内容；persona=观点/干货/人设内容），再按判定输出
  对应分析：persona 走内容质量拆解（结构/高光/可复刻点），leadgen 走**获客打法拆解**（内容
  模式/引导话术清单/CTA 密度与位置/转化路径/可复制打法卡）；判定结果回写样本行并随选题候选
  入库（脚本工场投放类型默认读它，可手动改）。获客号挖掘信号=**评论区求带密度**（求带/报名/
  私信类评论占比 ≥8% 判获客型，发现流程自动探测 Top3 样本并按获客优先排序）。
- **R3.9** **脚本按投放账号类型分风格**：脚本工场生成时选投放账号类型
  （人设号/获客号，默认读选题来源类型）——人设号禁一切引导话术（现有红线）；获客号要求
  获客引导（结尾行动指令+利他包装的扣字/私信设计，合规红线仍约束产品承诺）；打磨按类型
  应用对应红线。
- **R3.5** （边界）视频号自动扫描：平台无公开网页接口，**不做**；本地上传拆解为替代路线。

## R4 视频生产线（不做）

- **R4.1~R4.5** 口播原片上传/ASR 对齐/剪映模板草稿/素材库/B-roll 匹配 **整块不做**：
  数字人成片（原 R10）不在系统范围，不经过剪映草稿剪辑；产线止于脚本与图文内容。
  storyboard 分镜（R2.4 定稿产物）保留为**拍摄/口播提示**，不再驱动草稿生成。

## R5 公众号

- **R5.0** **每日一篇直出**（原「报题即草稿」；手动报题线已随死链拆除，pending 草稿只由
  直出链自动建）：每晚 0 点站外热点×画像
  提炼**唯一一个**最锐切角建 1 篇草稿，**自动链发 article_generate 成文**——早晨草稿箱里是
  一篇完整长文，人工改稿渲染后发布。没有值得写的热点时允许空过（宁缺勿滥）。
- **R5.1** 从定稿脚本（或直接从选题）生成长文，**深度版唯一档位**（feed 信息流版
  不在系统范围）：3000~5000 字，铺垫式开头（首段内）、机制拆解/方法框架/
  边界条件，判决句式标题、全文至少一个可转述的原创判断框架、术语必跟生活化类比、数字带体感锚点、
  关键知识点挂「人物+年代+冲突」一句话事实锚，自然收尾（不加转化引导话术）；
  风格库单选（**精选五视角**：深度研究/落地实践/问题深挖/对象解剖/方案对比），
  默认「**自动**」——生成开头按选题素材自动挑选最合适的分析透镜（无效回落深度研究）。
- **R5.1a** **数据论据国内源优先**（硬约束）：深研/脚本/长文大纲/长文分节四处生成
  一律优先国内公开数据、行业报告、国内企业实践（注明来源与年份）；国外机构数据只在国内无同类
  口径时作补充，不作主锚点。
- **R5.5** **ima 知识库数据源**：知识库内容产线（挖掘器/改编器，R5.6b）的原料来自
  腾讯 ima 用户**自建库**（订阅的他人库不是自有经验，不作素材源）。开关与凭证存
  app_settings（ima_kb_enabled / ima_client_id / ima_api_key / ima_kb_ids，DB 手工配置、
  无设置页 UI），默认关。（历史注：人工报题写文的「检索取材+零命中=缺料不硬写」闸
  已随手动报题线拆除，2026-11-14。）
- **R5.6** **知识库内容线**：自动供给线=**R5.6b 源文改编流**；手动报题线（报题建
  pending 草稿→检索 ima 取材成文）已拆除（2026-11-14，kb_topics 池退役后写文链无输入源）。
  知识库自动选题池（自动遍历 ima 目录提炼选题入池待选、选用后成文）：**不在系统范围**——
  无端点/执行器/数据表（生产库旧表原地保留），历史草稿与成文不受影响。
- **R5.6b** **源文改编流**（产品原则：系统做全部工作，用户只做最终决策）：
  公众号自动产线=挖掘器→内容清单→
  改编器，两段自动衔接，用户只在两端决策（清单定夺与发布登记）。
  **挖掘器**（每日凌晨 4 点，ima_kb_enabled 门控）：轮读 ima 知识库目录（每日 ≤18 篇全文）
  逐篇评估——具体框架/可抄清单/带数字案例/反共识判断四维评分，**≥7.5 入内容清单**
  （一篇源文一项：标题/来源号/质量分/为什么好/改编角度/逐字原话 ≤3 处/栏目/优先级），
  低分落 low 防回卷重评；**改编器**（每日凌晨 5 点，同门控）：清单取项改编成文——保源文
  骨架+逐字原话 ≤3 处引用+判断口径/钩子换成我们的（1900~2200 字），过四道闸才进待发：
  原创度闸（源文原句搬运占比 ≤30%，超线自动降重一次）→ 去AI味机检+定向重写 →
  事实对源+读者弃读点双审校（不过先修订复审一次；计数退避：首次退回清单待改期重排，
  再犯落 low 不再天循环）→ 标题五维评分选主；
  图表/头图排版落 rendered 待发。当日账必落（挖掘/改编各记产出与原因，「成功但空转」按
  故障处理）。发布人工（R6.5）：复制去公众号后台发表 → 发布登记贴 URL → 48h 回流
  阅读/在看/涨粉/进线（北极星=周私域进线数）。
- **R5.4** 一页纸知识图解。**不做**：海报/图解/物料包三件不在系统范围，发布在系统外完成。
- **R5.2** 人工改稿（md 编辑保存）→ 公众号内联样式渲染 → 一键复制 HTML。
- **R5.3** 写作队列交互。「不做长文」永久出口与可恢复机制：**不做**
  （无 dismissals 机制与模型，不做即不生成）。

## R6 发布台

- **R6.1** 发布物料包。**不做**（同 R5.4：海报/图解/物料包三件不在系统范围）。
- **R6.2** 发布登记与回流：旧独立发布台账（多渠道物料台账）**不做**；文章级
  **发布登记+48h 回流做**（R5.6b/内容工场：人工发表后贴 URL 登记→48h 补录
  阅读/在看/涨粉/进线，北极星=周私域进线数）。

## 使用场景（产品怎么被用）

**核心心智**：打开工作台看欠账 → 点卡片进队列 → 按键清空 → 表格里查历史。

### 日常工作流（建议节奏）

```
① 定时自动扫描同行（R3.4c）→ 新视频自动拆解 → 选题库队列清审（A/S/X）
② 随时有 idea：选题库顶部输入一句话回车（1~2 分钟出报告+评分）
③ 定审选题 → 脚本工场一版精品直出（自动打磨一轮）→ 定稿
④ 长文：公众号队列 A 生成 → 展开改稿 → 渲染 → 复制到公众号后台（发布人工，发布数据不进系统台账）
```

### 统一交互契约（X1 的用户视角）

- 队列快捷键：选题 `A定审/S跳过/X否决`；脚本 `1/2/3选版、A定稿、P打磨、S跳过`；
  其余页 `A主操作/S跳过`；全站 `Esc` 退出；输入框聚焦时自动屏蔽防误触。
- 慢操作有进度提示（定稿约 80 秒、打磨 3~6 分钟属正常）。

### 常见问题（FAQ）

| 现象 | 处理 |
|---|---|
| 深研显示"联网检索未生效" | DDG 偶有限流，报告仍产出（降级已明示）；要更稳在设置页切 auto/glm（需智谱按量余额） |
| 在线拆解/扫描失败 | 可能触发验证码，重试；仍失败用本地视频拆解（失败原因在任务详情可见） |
| 假数据进了评分 | 删该选题记录重新评估（评分只由内容本身决定，R1.6）；测试残留用 `acceptance/hygiene.py` 只读体检定位（TDD §13.6） |

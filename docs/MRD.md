## 0. 执行摘要

调研要回答三个问题：**这个内容生意能不能用一套系统做起来？哪些环节直接借开源？哪些风险必须用产品约束规避？**

三条最重要的判断（对所有同类生意都成立的通用结论）：

1. **定位是"AI 辅助的内容工厂"，不是"AI 内容生成器"。** 内容生产者的真实人格与交付能力是信任资产；系统价值在于把每条内容的生产时间从半天压缩到 1 小时以内，而不是替人生成空洞内容。
2. **发布环节保留人工确认，内容环节全自动。** 抖音 2025 年起专项打击"工业化批量发布同质化内容"，公众号个人号 2025 年 7 月后 API 发布权限已被官方回收。全自动发布是高风险低收益的环节，砍掉。
3. **同行数据获取走半自动路线。** 抖音反爬极强（a_bogus 签名 + 法律风险），不做规模化爬虫；系统负责"贴链接 → 本地下载 → 本地 ASR 转写 → LLM 拆解"，零合规风险。

## 1. 业务模型 → 内容策略映射

部署者应先把自己的商业模式写成三段式（前端引流 → 中端交付 → 后端转化），
再映射成三路内容漏斗——这是整个选题库的骨架。模板：

| 业务环节 | 优先级 | 受众 | 内容方向 | 载体 |
|---------|------|------|---------|------|
| ① 前端：引流业务 | 按运营定 | 目标客户决策者 | 行业案例、认知纠偏、降本增效 | 口播短视频（抖音优先、视频号同步） |
| ② 中端：核心交付业务 | **最优先**（内容资源倾斜） | 企业决策者 | 交付复盘、方法论、结果展示 | 公众号深度文 + 短视频案例 |
| ③ 后端：转化业务 | 想入行/进阶者 | 入行路径、技能、怎么开始 | 短视频引流 + 公众号长文转化 |

同一条选题往往可以一鱼两吃（既打动客户又展示给转化受众），选题库数据模型因此支持**一题多受众**标记。

内容节奏参考（成熟双载体打法）：每周 3~5 条口播短视频 + 1~2 篇公众号文章，
公众号文与当周视频选题联动，视频做流量、文章做信任与转化。

## 2. 竞对与对标调研

**竞对定义方法**：竞对不是泛商业/IP/AI 科普博主，而是——
**在部署者所处赛道，用同样的载体（口播短视频）直接获客的博主**。
判定三要素：内容主题 × 载体 × 变现方式。三者齐备才是竞对；只满足其一是方法论参考。

**竞对发现路径**：① 抖音/视频号站内搜索（赛道关键词）→ 按互动与评论区获客痕迹筛；
② 从已确认竞对的视频关联推荐与评论区@顺藤摸瓜；③ 本系统同行扫描持续监控，新冒头账号自动进拆解流水线。

### 2.1 A · 直接竞对（模板）

| # | 账号 | 定位 | 主平台 | 获客方式 | 验证方式 | 状态 |
|---|------|------|--------|---------|---------|------|
| 1 | （填真实账号） | 一句话定位 | 抖音 | 获客方式 | 主页复核通过（简介+作品列表实测） | 核心竞对，持续监控 |
| 2 | （候选池账号） | … | 抖音 | … | 话题挖矿已解析 bio | 候选池：已验证简介，防扫描过重暂不入监控 |

**账号评分口径（实测）**：
**相关性**＝贴合"赛道主题×口播×短视频获客"三要素；**质量**＝近期互动（近 10 条作品均赞/峰值）+内容实质与可模仿度；
**综合**＝相关性×0.6＋质量×0.4。
**监控门槛**：质量分低于阈值（示例 7.5）的从对标监控移除；新增对标必须达标。
高互动但相关性不达标的账号拒绝入监控——互动再高也不是同类，泛号是"精准"的反面教材。

**普查方法与边界（实测记录，随平台变动需复测）**：
- 零 cookie 可用：视频页 detail/related/mix 拦截（相关流可用但会漂移到泛商业号，需按主题过滤+人工确认）；分享主页 `share/user/<sec_uid>` 移动 UA 可出简介+近期作品；话题挖矿接口只吐视频不吐作者，且翻页失效——需再走视频 detail 反查作者；
- 零 cookie 被登录墙挡死：抖音站内搜索、话题页、移动端搜索——headless 下均不出数据；**按昵称反查 sec_uid 零 cookie 无解**（搜索引擎只见标题不见视频 id）；
- 长效机制：本系统同行监控（锚点视频模式）持续捕捉已确认竞对的相关流新面孔，人工确认后入表。

### 2.1 B · 方法论参考（非竞对：不同赛道，只学打法不学选题）

| # | 账号（脱敏） | 类别 | 变现方式 | 可学点 |
|---|------|------|--------|------|
| 1 | 某商业培训矩阵 | 商业培训 | 阶梯课程（引流课→私董会） | 定价阶梯与工业化矩阵切片 |
| 2 | 某咨询 IP | 商业咨询 | 课程+咨询+年度演讲 | "深度文 + 口播"双载体互导 |
| 3 | 某知识付费头部 | 开发者/垂直社群 | 星球+训练营 | 免费内容建信任→付费社群→陪跑 |
| 4 | 反面教材若干 | 卖课型 | 卖课（有翻车史） | 只学钩子技术不学交付必翻车：宣传与交付不符是共同死因 |

### 2.2 赛道时机判断（调研来源框架）

- 赛道热度：找权威媒体的岗位/行业增速报道与认证体系动作作锚点（附来源与日期）；
- 竞争密度：站内成熟个人 IP 数量决定窗口期；
- 站内数据外部搜索引擎不可见时，精确数据用蝉妈妈/新榜补查。

### 3.2 按四大模块的选型结论

- **① 选题/拆解**：下载走 Playwright 零 cookie 直连（主路线）（Evil0ctal 容器已随签名失效移除）；
  选题来源=idea 深研 + 同行监控扫描（**全网热榜类组件不采用**，与获客无关）。
- **② 脚本**：参考 MoneyPrinterTurbo 的 LLM 文案模块与 Prompt 工程（MIT、最活跃、Prompt 最成熟）+ ShortGPT 的 pipeline 抽象设计；实际实现为自研轻量脚本工场。
- **③ 剪辑**：调研结论=pyJianYingDraft（Apache-2.0）是唯一贴合"口播模板化剪辑"的开源组件（模板草稿替换素材/字幕/B-roll）。**最终不采用**（用户裁定）——成片改由口播数字人（PRD R10）直接产出，不经剪辑软件；素材库/ASR 对齐/草稿整线移除。
- **④ 公众号**：doocs/md 的 MD→公众号内联样式 HTML 渲染逻辑（WTFPL）。**已确认不做自动发布**，wechatpy 移出核心依赖。
- **分发**：人工发布（R6.4 裁定，social-auto-upload/sau 集成已移除；物料包辅助人工操作）。

## 4. 系统方案设计

### 4.0 复用边界：重活全在开源上，自研只写"胶水"

本方案的能力层面约八成来自开源/现成组件，按四种方式复用：

| 复用方式 | 组件 | 说明 |
|---|---|---|
| **独立部署，API/CLI 调用**（代码零耦合） | 下载走 Playwright 浏览器直连（进程内），无独立部署服务 | Docker/进程级部署，我们的代码只发 HTTP/shell 调用，天然规避 GPL 传染 |
| **pip 库直接引入** | faster-whisper（ASR）、Pillow/matplotlib（配图与图表） | MIT 等宽松许可，作为依赖装进项目 |
| **直接抽取代码**（license 宽松） | doocs/md 的 MD→公众号 HTML 渲染器（WTFPL）、MoneyPrinterTurbo 的脚本生成 Prompt 模板（MIT） | vendor 进仓库或按 MIT 摘录，不重写 |
| **仅参考设计，不抄代码** | ShortGPT 的 pipeline 抽象、NarratoAI 的时间轴对齐思路 | 停滞/形态不符的项目只取思想 |

自研的只有三层，且这三层在开源世界不存在现成答案：

1. **Web 控制台与工作流编排**——调研的 19 个项目各管一段（下载/转写/草稿/排版/上传），没有一个提供"选题库 → 脚本工场 → 口播数字人 → 公众号工作台"的完整形态；最接近"一体化创作台"的 OpenCreator（11.4k stars）无 license 不能抄，且面向无出镜的生成式视频，形态不符。
2. **数据模型与内容资产状态机**——三段式业务的受众标记、选题评分维度、文-视频联动规则，是业务逻辑不是通用功能，只对部署者的生意成立。
3. **Prompt/结构模板库**——从对标拆解中持续沉淀的业务资产，这是系统真正的护城河，只能自己长出来。

两个刻意"不整体复用"的决定：不 fork MoneyPrinterTurbo / NarratoAI 做项目主体——它们是"素材混剪/解说"流水线，与"口播数字人"形态不同，带着一身不需要的重量做二开，比写胶水更慢更难维护。代码量预估：自研部分约几千行 Python（编排+API）+ 前端页面，视频引擎、ASR、爬虫、排版引擎一行都不用写。

```
│  │ 定稿脚本 → 数字人引擎            │  │ 选题/脚本 → LLM 长文生成       │   │
│  │ (克隆形象/复刻音色/自动字幕)     │  │ → Web 编辑器人工改稿          │   │
│  │ → 1080×1920 竖版成片直接产出     │  │ → MD→公众号HTML(一键复制)     │   │
│  │ (不做剪辑软件/草稿路线)          │  │ → 人工去公众号后台粘贴发布    │   │
│  └─────────────────────────────────┘  └────────────────────────────────┘   │
│   storyboard 分镜保留为拍摄提示       ┌── 模块五 发布台与数据回流 ─────┐   │
│                                       │ 发布物料包(一键复制标题/话题)  │   │
│                                       │ 发布动作永远人工(R6.5)         │   │
│                                       └────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────────────┘
```

设计原则：**SQLite 单库存一切**（租户/成员/积分台账 + 选题、脚本、视频资产、文章），每条内容是一个带状态机的资产对象（`idea → topic → script → shot → edited`），登录门禁 + 租户隔离的 **Web 控制台**驱动全流程，任何环节都可人工介入，发布永远人工。

### 4.2 模块一：选题中心

- **idea 深研**：随手输入一句话 idea，Agent 做深度研究（联网检索 + 结构化输出：选题方向、目标受众、痛点假设、钩子候选、与业务的匹配点、竞品内容情况），产出入库。
- **同行拆解**：维护对标账号清单（现行监控名单以同行监测页/§2.1A 评分口径为准）。流程：刷抖音看到好视频 → Web 端贴链接 → 一键完成：Playwright 下载 → faster-whisper 中文转写 → LLM 按框架拆解（钩子类型与位置/叙事结构/选题价值/评论区痛点/可复刻点）→ 结构化入库。**全本地处理，不做规模化爬取。**
- **同行监控**：对标账号扫描 → 新视频自动下载/转写/拆解 → 选题候选入库；这是"借势热点"的正确来源。
- **外部平台发现**：在外部平台看到值得拆的视频，直接贴链接进本系统，复用同一条拆解流水线。
- **选题评分**：LLM 按"业务相关度 × 受众痛点强度 × 差异化"打分排序，人工终审定审。

### 4.3 模块二：脚本工场

- 输入定审选题，套用结构模板库（钩子-痛点-方案-证明-收尾等范式，模板从对标拆解中持续沉淀），LLM 一次生成 3 个版本。
- 内置"批判 Agent"打磨循环：对每版脚本挑刺（钩子弱、说教、没有证明）→ 定向重写，最多 N 轮。
- 输出物：口播终稿（含停顿/重音/语气标记，直接进提词器）+ 分镜提示（哪里需要切 B-roll、哪里出字幕卡点）+ 标题/封面文案候选（抖音标题、视频号标题、发布话题标签）。

### 4.4 模块三：视频成片（口播数字人）

**成片路线 = 口播数字人直接产出**（PRD R10）：定稿脚本 → 克隆形象 + 复刻音色 TTS → 口型合成 → 平台自动字幕 → 1080×1920 竖版直接落盘，分钟级出片、无剪辑软件依赖。

调研阶段评估过的剪映模板模式（pyJianYingDraft 草稿替换素材/字幕/B-roll、素材库自动匹配、FFmpeg 全自动轨）**整线不采用**（用户裁定，见 §3.2 选型结论）；storyboard 分镜保留为**拍摄/口播提示**。

### 4.5 模块四：公众号流水线

- 选题/视频脚本 → LLM 生成长文（**双档位，2026-10-02 起**：feed 公众号版 1200~1800 字默认——信息流标题、开头即答案、无刻意转化话术；deep 深度版 3000~5000 字。旧「CTA 引流私域/课程」结构已废弃——质量尺对 CTA 直接扣分）。
- 输出 Markdown → Web 编辑器人工改稿 → 借 doocs/md 的渲染逻辑转公众号兼容的内联样式 HTML。
- **发布纯人工**（已确认不做自动化）：系统止步于"生成 → 排版 → 一键复制公众号格式 HTML"，在公众号后台粘贴发布。零接口依赖、零风控暴露。
- 文-视频联动：当周视频选题自动建议公众号选题，视频文案的深度版即长文骨架。

### 4.6 模块五：发布台与数据回流（辅助）

- **发布物料包**：每条视频/文章定稿时自动生成——抖音标题+话题标签、视频号文案、封面文案、公众号 HTML，Web 端一键复制。
- 发布：**永远人工**（R6.5）——发布台只产出物料包；sau 集成已按 R6.4 移除。

### 4.7 技术栈与项目结构

- **形态**：Web 站（已确认，不搞 CLI 优先）——浏览器打开即用，登录门禁 + 多租户（见 PRD R0.1/R11）
- **后端**：Python 3.12 + FastAPI（whisper、FFmpeg 生态全在 Python 侧），后台任务跑 ASR/下载/渲染等长任务，进度在 Web 端可见
- **前端**：React + Vite + Tailwind，构建产物由 FastAPI 静态托管（中文界面）
- **存储**：SQLite（+ SQLModel ORM），单文件备份即全量备份
- **LLM**：GLM 为主（已确认），预留 DeepSeek 备选开关
- **ASR**：faster-whisper（large-v3 起步，中文场景可测 FunASR SenseVoice 提速）
- **视频**：数字人引擎（蝉镜开放 API）直接出片 + FFmpeg（工具箱角色）

## 5. 可行性分析

### 5.1 技术可行性：全部绿灯，各有边界

| 环节 | 结论 | 关键边界 |
|------|------|---------|
| 选题（同行拆解） | ✅ 成熟 | 半自动（手动贴链接）；不做规模化爬虫（抖音 a_bogus 反爬 + 法律风险） |
| 脚本生成 | ✅ 成熟 | 纯 LLM 应用，无技术风险；质量靠模板库与打磨循环运营 |
| 视频成片 | ✅ 可行 | **口播数字人直接出片**（克隆形象+复刻音色+自动字幕，分钟级）；不做剪辑软件/草稿路线（用户裁定） |
| 公众号 | ✅ 简化 | 已确认纯人工发布：系统只负责生成与公众号格式排版，零接口依赖、零风控暴露 |
| 抖音/视频号发布 | ⚠️ 半自动 | 官方 API 需企业主体；Playwright 自动化可用但有风控风险 → 保留人工确认 |
| ASR 中文转写 | ✅ 成熟 | faster-whisper large-v3 + VAD；SenseVoice 更快更准可测 |

### 5.2 检索通道事实（实测口径）

智谱平台**支持 web_search 工具**；可用性取决于 key 的计费通道：
Coding Plan 套餐端点**不含**搜索工具（实测模型报"没有可用的搜索工具"）；
按量 PaaS 端点可用，需该 key 有按量余额（余额不足报 1113）。
结论：要用 GLM 搜索 → 给 key 充按量余额 → 设置页切 auto/glm。
（DDG 通道在境内直连不可用，检索通道可在设置页切换，详见 search 模块。）

### 5.2b 成本估算：月成本一杯咖啡

- **LLM API**：按每月 100 条脚本 + 20 篇长文 + 拆解/评分用量，含 3 倍迭代冗余约 170 万输入 + 85 万输出 tokens → 主力模型约 16 元/月；全用旗舰模型也就 30~60 元/月。
- **ASR**：本地 faster-whisper，0 元。
- **数字人**：按成片秒数计费（第三方 API，见设置页平台成本卡）。

### 5.2c 定价体系

部署者自定（定价阶梯参考行业范式：低价引流课 → 高价私董会/陪跑）。

### 5.3 风险与合规

1. **平台合规（最重要）**：《人工智能生成合成内容标识办法》2025-09-01 已施行——AI 辅助生成的文案发布时应勾选"AI 生成"声明；抖音 2025 年《恶意营销号治理规范》专项打击"工业化批量发布同质化内容"。→ **对策：原创口播 + 保留人工内容把关 + 发布环节人工确认 + 主动勾选 AI 声明**。
3. **抖音下载工具失效风险**：平台风控更新可能使下载功能间歇失效。→ 对策：Playwright 真浏览器拦截为主路线（随平台变动持续实测），失效期用本地视频上传拆解兜底。
4. **数据安全**：密钥在服务端 `.env`（不入库不入前端），账号体系走登录门禁 + 会话；多租户数据按租户隔离。

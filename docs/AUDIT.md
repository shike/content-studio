# AUDIT · 审计规程与检查清单

> 本文定义"如何全面验证这个项目"，是规程不是快照：不含版本号、不含当前完成情况；
> 每次审计按 §2 执行、按 §3 清单逐项核对，结论在会话/工单中交付，不回写本文。
> 测试脚本层面的方案见 TEST.md；需求基准见 PRD.md；契约基准见 TDD.md。

## 1. 审计维度

| # | 维度 | 回答的问题 |
|---|---|---|
| A1 | 验收执行 | 全部验收脚本（P0-P7）是否全 PASS（含 SKIP 是否都有正当外部依赖原因） |
| A2 | 接口契约 | 运行中端点与 TDD §6 契约是否一致（多出的端点有没有 PRD 依据） |
| A3 | 界面冒烟 | 每页是否零报错、JS 零异常、页面默认表格视图（队列仅手动进入）、操作有状态回显、登录门禁生效 |
| A4 | 数据卫生 | 库里有没有测试残留/演示数据（自动化：`acceptance/hygiene.py`，见 TEST §6） |
| A5 | 性能预算 | LLM 耗时/超时/max_tokens 是否在 TEST §4 基线内；成本按用途分账是否正常累计 |
| A6 | 需求覆盖 | PRD 每条 R/X 是否能指出验证方式（脚本项/手测项） |
| A7 | 内容质量 | 抽查生成内容按 TEST §5 评分细则复核（质量阈值不被稀释） |
| A8 | 租户隔离与口径 | 双租户互不可见、越权 404、归属正确、租户侧零金额零品牌、扣分流水完整（P7 全绿 + 抽查响应体） |

## 2. 执行步骤

1. **隔离环境**（A1/A4 强制）：`cp -R data data-acceptance` → 清继承队列与会话 → 重置已知口令 →
   `DATA_DIR=data-acceptance` 起独立实例（如 :8200）→ 跑 P0-P7 → 停实例并 `rm -rf data-acceptance`。
   环境变量与命令见 TEST.md §2/§3。
2. **契约核对**（A2）：`GET /openapi.json` 取全量端点清单，逐条对照 TDD §6；
   同时反向核对——前端 `api()` 调用的每个路径都有后端实现。
3. **界面冒烟**（A3）：浏览器逐页打开（工作台/选题库/脚本工场/口播数字人/公众号/发布台/
   海报提示词/同行监测/我的风格/拆解库/话题雷达/任务/设置/管理后台），
   注入 error/unhandledrejection 监听，检查报错横幅；另以普通成员身份复核租户侧信息白名单
   （R11.6）与一次性密码首登强制改密（R11.2）。
4. **数据卫生**（A4，对生产库只读检查）：核查 publish_records 是否含演示链接/假数据；
   topics.score 与 score_breakdown.base 的差是否都能由真实 metrics 解释；
   benchmark/articles/scripts 是否残留 fixture 行。
5. **性能基线**（A5）：llm_calls 表按 purpose 统计 latency 与 tokens_out，
   对照 TEST §4 预算（打磨 ≤6 分钟、定稿 ≤2 分钟、轮询预算长文 1200s / 脚本 900s / 深研·打磨 600s / 定稿 360s、max_tokens 余量表）。
6. **覆盖对账**（A6）：沿 PRD 逐条 R/X 标注"验证方式"，无验证方式的条目列为审计缺口。

## 3. 检查清单（逐项打勾）

- [ ] P0-P7 全部 PASS，SKIP 项均有外部依赖原因
- [ ] openapi 端点数与 TDD §6 契约一致；无"有端点无 PRD 依据"的多余项
- [ ] 前端调用的每个 API 都存在且语义一致
- [ ] 全部页面渲染零报错、控制台零异常；未登录访问业务页被门禁拦截
- [ ] 页面默认表格视图；审阅队列手动进入后键盘可用（A 定审 / S 跳过 / X 否决 / Esc 退出）；「不做」专指公众号「不做长文」永久出口
- [ ] 生产库无测试残留（fixture 行、demo 链接、假 metrics）
- [ ] 每个非 base 评分增量都能溯源到真实发布数据
- [ ] 思考型模型调用无 JSON 截断（tokens_out 未贴 max_tokens 上限）
- [ ] PRD 每条 R/X 均有验证方式
- [ ] 用户侧操作项（平台凭证充值）不缺失、未被当成代码任务
- [ ] 租户隔离抽查：第二租户看不到首租户数据、越权读 404、租户侧响应无金额与引擎品牌、
      积分流水与扣减一致、停用/删除租户后成员即失效
